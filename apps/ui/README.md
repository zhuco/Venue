# UI 入口

两套 UI 固定放在本目录同级位置，避免把桌面终端需求误改到用户 Web：

- `desktop/`：VenueFlow 原生桌面终端，Rust + eframe/egui。凡是桌面截图、K 线、盘口、交易对标签、下单面板、工作区布局与桌面快捷键，先从这里定位。
- `web/`：浏览器用户界面与同源 BFF，Next.js + React。凡是 URL 路由、Cookie 会话、邀请注册、KOL 落地页、响应式浏览器页面与 Web API，先从这里定位。

两端只共享 `crates/venue-control-protocol` 等明确协议，不复制交易规则、凭证或执行实现。目录改名或主要入口变化时同步更新根 `Cargo.toml`、`.github/workflows/workspace-gates.yml`、`docs/CODEMAP.md`、`docs/WEB.md` 与本文件。

机器人授权、配置上限及 KOL 生命周期统一见 [带单同步](../../docs/LEADER_ORDER_MIRROR.md)；支撑分批做多的已实现接口与增强门见 [策略契约](../../docs/SUPPORT_MARTINGALE.md)。本页保留桌面呈现与交互边界，Web 会话和部署见 [Web 指南](../../docs/WEB.md)。

桌面机器人页的 Grid 新建与配置编辑使用模态对话框，长表单滚动、保存与取消固定在表单下方；草稿绑定打开时的凭证，账户切换、实例版本变化及请求待确认期间禁止提交。KOL 新建/编辑对话框维护名称、说明和策略资金，只有停止态且无未决工作时可编辑；启用仍需逐实例风险确认，停用撤销程序子单但不平仓。权限查询失败显示接口错误，不冒充无权限或已接入。

机器人页统一列出当前账户的人工带单、网格和马丁做多。新建菜单选择类型，管理及编辑分别打开独立窗口，不在列表下常驻重复详情。运行中的人工带单可打开配置查看，保存仍要求停止且没有未决工作。

马丁做多首个桌面闭环使用 Bybit LIVE 执行；支撑位模式使用 Binance USD-M 参考行情，固定价格模式按每币入场阈值和补仓跌幅决定市价买入。逐币止损默认关闭，可选固定价格或持仓均价下跌百分比；启用后由共享 Executor 监测签名标记价，先撤本策略止盈，再按当前持仓发送只减仓市价止损。触发后暂停整个实例增险，拒单需人工处理；不保证指定价格成交。保存只建立停止态实例且失败保留草稿；启动前必须完成当前 revision 的只读签名预检并确认参数，Control 在 Start 时重做同一预检。生命周期、健康原因、预检失败与控制请求不确定分别展示；控制请求超时不冒充订单 `ReconcileRequired` 或成交。

状态栏分别显示 Control 快照与 SSE 连接状态；账户刷新失败、时钟不一致和事实过期分别提示。非 Binance 账户通过既有独立策略 Gateway 读取签名账户快照，不等待冻结 Node；首次读取显示“正在读取账户”。Net/Hedge 模式按实际账户呈现。悬停可查看服务器事实及桌面接收的时间差，原有 15 秒私有事实有效期和交易保护保持不变。该读取入口不授予 Binance 手动订单接口跨所发送权限。

桌面警告诊断写入 `%LOCALAPPDATA%/VenueFlow/desktop.log`，每次启动覆盖该 UI 日志，不依赖启动器持续读取 stdout。日志不可用时丢弃诊断输出，避免日志阻塞后台网络线程；它不保存交易恢复事实、凭证或私流原文。

桌面账户与 Control 客户端访问 `localhost` 或回环 IP 时直接连接，不经系统 Internet 代理；远程 HTTPS 继续遵守系统代理设置。私流订阅停止、切换及持久化失败时，Executor 清除旧投影的健康标记，保留其原始事实时间及内容。

普通终端用户免费注册使用 `/v2/account/terminal/register`，不要求邀请码；Web 跟随者注册使用 `/v2/account/register`，必须填有效邀请码并固定 KOL 归属。KOL 角色只能由管理员开通。两端共用登录与凭证，不要把 Web 邀请注册接到桌面“注册”按钮。

桌面账户列表只读取新 Executor 的用户作用域 `TerminalAccountProjection`；历史委托读取其命令账本，仓位历史为最近 500 条已观察变更。冻结 Node 数据不作为列表回退来源，机器人页也不再显示旧策略重复列表；清理这些 UI 入口不删除旧恢复工件或停用运行实例。

历史委托保留 Grid 的不透明账本编号（最长 128 字符），不能按账户 UUID 过滤或使整个列表失败；终端/跟单命令编号、账户和请求编号仍按各自既有规则校验。

API 表格、执行账户选择和 Windows 登录会话恢复统一见 [账户管理](../../docs/ACCOUNT_MANAGEMENT.md#进程与状态)。

历史成交使用 18px 圆角标识：买入为绿色 B，位于对应 K 线下方；卖出为红色 S，位于 K 线上方。同根 K 线的同方向成交按 20px 间距向外排列，每笔保留独立标识和真实成交数量、价格悬停详情。

订单簿在当前账户限价挂单对应的买/卖档位价格前显示黄色小圆点，同价多单合并为一个点。标记匹配当前行情交易所、账户、交易对和精确价格，随既有签名挂单投影更新；只遍历现有挂单并使用固定大小的可见档位标记，不增加交易所查询、订阅或刷新频率。

图表每笔实际委托只绘制一个分段标签（类型/价格、剩余数量、X），标签中心固定在委托价格线上，同类标签左侧对齐，邻近价格的标签允许直接重叠，不进行横向或纵向避让；虚线从标签右侧开始，不穿过标签。最新价为无文字标签的灰色短虚线（开启价格标签设置也不增加标签），持仓成本线为蓝色短虚线，委托短虚线按买卖使用绿/红；每段至少保留两个物理像素，避免缩放取整后消失。挂单使用 20px 紧凑分段标签、实心方向色标题块和深色数量/操作区；持仓标签以“盈亏±金额”开头，方向及成本价在悬停详情中显示。反开箭头和平仓 X 绑定该仓位，先核对当前账户与新鲜持仓，再打开既有确认框；不会在图表点击时直接发送交易。X 复用终端精确撤单；账户过期或撤单待确认时禁用操作，未知成交量显示“—”。拖动显示黄色新价格预览，松手打开“撤单并重新挂单”确认框。确认通过既有精确撤单接口的 `replacement_price` 提交，Control 在同一事务写入撤单与待释放新单；Executor 按原身份签名确认旧单终态，扣除最终累计成交量后才释放新单。新单保留原 GTC/Post Only 类型、买卖方向和开平仓属性，仅改价格；平仓仍按新鲜签名持仓裁剪。类型不明、非普通限价单或未成交量不明在撤单前拒绝；已全部成交不新挂，撤单失败/未知不释放，新挂失败不恢复旧单。账户切换使旧确认失效，桌面关闭不撤销已入账操作，不自动重发。

图表挂单只来自当前账户签名投影，不额外叠加本地请求标签；部分成交显示剩余数量，签名投影移除已成交/撤销订单后同步移除对应标签和价格线。手动请求进入发送队列仍即时重绘；精确撤单目标先隐藏，明确失败恢复，撤单结果不确定时恢复原线并禁止重复撤单。乐观撤单仅存在于内存图表状态，不修改签名持仓、订单、账本或重试行为；请求未完成期间重绘唤醒上限为 100ms，这是本地调度目标，不代表交易所确认延迟。

图表持仓标签和持仓列表共用本地浮动盈亏计算：多仓为（最新价－签名开仓均价）×数量，空仓反向，Net 按带符号数量计算；盈利绿、亏损红、零值中性。Binance 账户从同交易对逐笔成交/K 线与全市场 ticker 中选择更新的有效价格，无需等待账户轮询；其他交易所当前使用自身签名标记价在本地计算，不混用 Binance 价格。价格的交易所时间与本机接收时间都须满足既有 15 秒新鲜度门，盘口及连接心跳不能刷新成交价时间；否则回退签名标记价，缺少有效成本或价格时显示“—”。结果不含手续费/资金费，不改写签名事实或交易保护；增减仓后仍使用服务端确认的数量及成本。账户陈旧状态仍以黄点和悬停说明保留。

`terminal_feedback.rs` 将本地拒绝、HTTP 安全错误码、命令账本的拒绝/未知结果显示于底部状态栏，单行截断并在悬停时显示完整详情；下单面板不重复显示。历史委托保留原因及命令号。等待发送或命令已核对均不等于成交；超时不自动重试，原始响应/密钥不进入提示。发送前错误按实际失败环节区分命令绑定、数量、价格、方向、订单类型、公共规则目录、请求准备、签名及账本冲突；规则目录失败不解释为数量不合规，绑定失败不解释为用户未选账户。旧 `not_dispatched_invalid` 只说明未发送且未记录具体原因，不枚举可能原因或猜测为币安拒单。

全市场 ticker 批次校验失败时丢弃该批并记录诊断，不重连共用的 K 线、逐笔成交及盘口连接；旧报价继续按真实时间过期，后续合法批次恢复更新。网络关闭、心跳超时及队列故障仍触发原有重连流程。

手动 Post Only 开多/开空不依赖持仓投影就绪或新鲜度：UI 只检查账户选择、有效正数输入及既有 Maker-only/选价约束；Control 校验本人已验证凭证、权限、旧链互斥和请求幂等。Executor 使用共享公开规则缓存与已校时时钟，按步长向下取整后直接提交，不为开仓读取完整账户/持仓快照。最低名义、余额、价格过滤及 Post Only 拒绝由 Binance 判定，安全数字错误码以 `binance_<code>` 入账并显示。平仓和撤单仍走既有签名事实保护；自动 Grid/Copy 不走此手动开仓分支。

Executor 手动开仓在读取加密凭证的同一查询中核对命令账户与验证状态，不再另查一次。逐行及右侧市价平仓/反开的持仓读取合并凭证、账户归属与私流健康条件，只读取已保存投影及较新的市价操作持仓回读，不加载成交历史或仓位历史。发送前仍按 15 秒内有效持仓裁剪数量；常规市价操作先 POST、后刷新该交易对持仓。限价平仓的签名订单/持仓与预留量检查保持原路径。

资产页与底栏使用同一份签名资产快照。当前报价币没有独立余额时，可显示明确标注为 USD 的统一账户权益；不将 USD 冒充 USDC/USDT，也不把仓位事件时间当作资产重新签名时间。资产目前不随仓位事件实时刷新。

## 远程 Control 的桌面启动

六所公共行情自动通过 HTTPS 只读时间接口建立独立显示时钟，随后按单调时间推进，不要求用户修改 Windows 时间或取得管理员权限。每 60 秒刷新；同步失败最多保持 5 分钟，之后行情转陈旧并等待恢复。时间样本往返超过 3 秒或出现异常跳变时拒绝；按完整往返延迟保守估计数据年龄，不修改交易所原始时间或放宽未来数据检查。此时钟仅供公共行情显示使用，不参与账户签名及交易保护。时间源为 [Bybit 公开时间接口](https://bybit-exchange.github.io/docs/v5/market/time)。

顶部常驻“设置 / Settings”直接打开通用页，语言选项在此切换中文/English，并随桌面偏好保存。行情下拉独立于执行账户；新增 Bybit、Bitget、Gate、OKX、Hyperliquid 公共永续行情入口由各 `venue-gateway-*/display.rs` 归一化，经固定 HTTPS 只读代理提供合约目录、K 线、盘口、近期成交和报价。Binance 保留原 WebSocket 链路，新增五所为 REST 快照轮询（最短 2 秒，不承诺逐笔完整流）；Gate/Bitget 当前目录限定 USDT，Hyperliquid 为默认 DEX 的 USDC。Hyperliquid 报价明确标为 Mark，OKX 缺失的实际计价成交额显示“—”。切换行情源清空旧行情，不切换执行账户；非 Binance 参考行情禁止直接用于 Binance 手动选价。新增链路须通过代理部署、联网与桌面窗口验收后才能视为可用。

桌面 Control 账户事件流与账户私有投影均只订阅当前执行账户。服务端确认账户切换后，私有投影订阅保留最新选择并立即唤醒读取，取消旧账户未完成的只读请求及轮询等待；相同订阅不重复唤醒，私有投影、历史与提交/撤单/仓位回执（包括空结果、错误与 401）必须同时匹配本地选择代次、credential、trading account 和 venue。选择发生的同帧立即进入 account-switch-pending，清除选价、已武装动作、订单选择与确认框，构造及发送边界同时关闭；切换失败不恢复旧意图。overview 确认所选凭证及账户后才重新开放已支持的动作，平仓/撤单仍等待新鲜私有事实。已进入耐久链的命令不因桌面切换取消或重发。切换时关闭旧事件流，停止续订旧账户的 UI 投影租约，租约按既有到期机制回收；后台运行中的 Grid、带单或跟单所需私有流独立保留。该范围由 `desktop/src/client/stream_gates.rs` 控制，迟到的全账户快照不能恢复旧订阅；订单发送仍使用独立通道，不因读取取消而中断。

持仓列表的 PnL 固定 4 位小数，操作列替代更新时间。逐行平仓/反开及右侧市价平仓统一走 `terminal_position.rs` 协议；行目标不随图表切换。服务端复用已获取的新鲜仓位按上限发送，正常路径先市价 POST、再读取该交易对持仓刷新统一投影。反开先确认原腿平仓，再按实际成交数量开反向，失败/部分成交/超时不继续增仓；用户确认框说明滑点、反向仓位追加及运行策略不会自动停止。

桌面端默认访问 `https://clawdbotweb.site`，可直接双击 `venueflow.exe` 后登录，不需要 SSH、环境变量或本机数据库。设置 → 通用中的“服务器地址”支持修改、恢复默认和应用并连接；未应用的编辑不改变当前连接，切换地址清除旧会话及私有投影。远程地址必须使用受信任证书的 HTTPS，本机调试可使用 HTTP。公共行情的三条 Binance USD-M REST 路径和两条组合 WebSocket 路径也经该 HTTPS 主机的精确只读反代访问，客户端不再要求所在网络可直连 Binance；该反代不接收账户凭证，也不开放任意上游或路径。

旧 schema 2–6 保存的精确开发默认地址 `http://127.0.0.1:39180` 在升级时一次性恢复为启动默认值；自定义地址和升级后主动设置的本机地址保留。系统凭据库按 endpoint 隔离，旧隧道会话不会转移到 HTTPS，需要重新登录。`VENUE_CONTROL_URL` 仍可指定未配置客户端的启动默认值。

服务器复用既有 Caddy 域名与 `venue-kol-caddy-route.service`：`scripts/configure_desktop_https.py` 只在该域名内增加精确 method/path 的桌面接口与无缓冲 SSE 转发，Control 继续监听服务器 `127.0.0.1:39180`。部署与重启恢复见 `docs/WEB.md`。

可选启动脚本默认也使用 HTTPS；开发人员需要旧 SSH 隧道时显式指定：

```powershell
G:\Venue\scripts\Start-VenueFlow.ps1 -SshTunnel
```

隧道选项只复用已有 SSH 凭证；若已保存其他服务器地址，须在设置中切换到本机地址。脚本不读取或保存 API Key、密码和会话令牌。

SSH 隧道诊断通过 OpenSSH `-E` 写入同目录的 `ssh-tunnel.log`，不占用启动器的输出管道。遇到持续 HTTP 超时应对比服务器本地接口和新隧道，确认故障连接后仅替换该隧道；服务器策略不依赖桌面隧道。

行情状态“行情更新延迟”表示超过 5 秒未收到有效行情，不表示合约下架；收到新的有效行情会自动恢复，悬停显示距上次有效更新的秒数。连接消息不刷新该时间。请求超时、断线重连、自动校时、接口限流或访问受限、合约不可用及数据校验失败分别使用中文说明。Binance 公共 WebSocket 与其他五所共用显示时钟，账户时钟与交易门禁保持独立。

终端委托历史在分页前限定 Binance 的 Terminal / Copy / Grid 命令，其他交易所的独立策略命令由各自查询链读取。历史刷新失败时，桌面把非终态回执标为上次记录，并提示状态待刷新；读取失败不改变账本状态，也不触发补单。
