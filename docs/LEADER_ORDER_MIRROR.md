# 人工带单与订单同步

本页定义管理员授权、机器人生命周期，以及限价单、市价单和止损单同步边界。注册、邀请固定归属、API 验证及新旧账户互斥继续遵守 [KOL MVP](KOL_COPY_MVP.md)。

## 授权与入口

KOL 身份、授权、邀请及托管跟随者归属于登录用户。带单源使用该 KOL 用户明确选中的执行账户；不聚合名下全部账户，也不永久绑定开通 KOL 时的凭证。当前执行账户与当前带单源必须在界面分别明确展示；多端会话不得形成两个同时生效的带单源。切换执行账户不撤销 KOL 身份，但带单源切换必须先停止旧源新增同步、按原身份结清未决命令并撤销旧子单剩余量，再建立新源的签名基线；未完成交接时不得显示新源已生效，已有跟随仓位不得自动平仓或按新源重新解释。现有 profile/robot 固定账户字段仍需配套切换实现，不能只更新会话选择冒充已切换带单源。

- `venue_leader_bot_permissions` 按 KOL 用户授权；缺少记录或 `enabled=false` 均拒绝创建和启动。KOL profile 必须已启用，最多 5 个；邀请注册不会授予带单权限。
- 桌面机器人页读取 `GET /v2/kol/leader-bots`，在一个私有列表中混排 Grid 与人工带单；Web `/` 继续读取兼容的 `GET /v2/kol/leader-bot`。非 KOL 且没有实例时隐藏入口；KOL 资料存在但尚未获权时显示“待管理员授权”。撤权后的已有实例保留状态和停止操作。前端显示或隐藏均不构成授权证明。
- 创建只接受本人的已验证 KOL 主账户凭证；同一主账户最多保存 20 条带单配置，可在停止且无未决工作时编辑名称、说明和策略资金。跟随关系尚未选择具体机器人，因此数据库和 Control 均限制同一 KOL 最多一个非停止实例，防止同一源订单重复复制。客户端不能指定 owner、主账户身份或权限。
- Control 创建/启动校验数据库权限；Executor 在发送前再次校验 KOL、关系、机器人和授权版本，以及源订单仍存在且参数一致。普通 Grid 的权限独立。
- KOL 只获得自己的主账户信息、聚合跟随人数及待处理数量。跟随订单查询只返回当前登录跟随用户的记录。

管理员通过 `venue-leader-bot-admin` 维护授权，无公开 HTTP 授权接口。该工具只读取部署环境中的 `VENUE_CONTROL_ADMIN_DATABASE_URL`；数据库连接字符串不能放进命令参数、文档或日志。

```text
venue-leader-bot-admin grant <KOL用户UUID> 0 <操作者标识>
venue-leader-bot-admin revoke <KOL用户UUID> <当前权限revision> <操作者标识>
venue-leader-bot-admin migrate
```

首次授权的期望版本为 0，成功返回新版本。以后操作必须使用当前版本；过期版本拒绝，不覆盖别人的修改。每次修改保留审计记录。此工具只授权已配置的 KOL，不自行创建 KOL 角色或 API 凭证。

`migrate` 仅用同一管理员数据库环境变量安装并校验迁移，不启动 HTTP、Executor 或任何带单实例。Control 启动时仍用 `DATABASE_URL` 校验迁移；生产配置 `VENUE_CONTROL_RUNTIME_DATABASE_URL` 后，随即关闭迁移连接池，用户请求只使用权限受限的运行角色。未配置该变量的本地旧部署保留兼容行为，不能代替生产角色隔离验收。

## 生命周期

创建为 `stopped`。启动请求包含 request ID、expected revision 和明确风险确认；同一请求重放复用结果，过期状态拒绝。启动还检查主账户、旧 Node 占用和本实例历史未决工作。

停止或撤权进入 `draining`，停止规划新单，取消尚未发送的子命令，并对已挂出的子单产生精确撤单。已经发送但结果未明的请求继续按原身份对账。所有映射和命令结束后才显示 `stopped`；已有仓位不会自动平仓。重新授权不会自动恢复运行。

明确失败的撤单最多尝试 8 次，间隔至少 30 秒，并要求新鲜跟随账户投影。达到上限显示 `needs_attention`；用户再次点击停止可开启新一轮清理。`Sending/Accepted/ReconcileRequired` 不因重试清理而改写或重新发送。

停止时，未收到原生订单身份、无已确认接受或成交的普通开仓限价请求可执行有限历史核对：该账户只能有这一条未决命令，原发送已超过 60 秒，查询区间包含命令创建前 60 秒且不超过 48 小时；同一 clientOrderId 两次签名查无订单，完整区间的签名订单历史和成交均为空，同时新鲜签名账户无持仓、普通或条件挂单，才将原命令置为 `cancelled` 并结束映射。此状态表示停止目标已确认，不伪造交易所订单终态，也不补发旧单。迁移 `0042` 将核对事实保留在原命令的不可改写 `mirror_stop_readback`；事务锁内重查停止版本、账户归属和事实新鲜度。单次查无、历史查询失败、任意历史记录、已有原生身份或超出时间窗口仍保持原身份对账。停止完成后须由用户重新启动带单。

## 同步规则

认证账户流和签名 REST 恢复产生统一的活动订单投影。规划只使用健康且不超过 3 秒的投影；客户端点击、ACK 和展示缓存不能产生跟单交易。

- 只同步创建时间晚于本次机器人启动和关系激活的普通 UM 限价单、经认证成交事件或签名精确查单确认的 `MARKET` 源单，以及当前 Algo 接口中的 `STOP_MARKET`。关系的允许交易对留空表示允许当前 Binance USDⓈ-M 目录中全部在交易的 USDT/USDC 永续合约；填写时只允许白名单内交易对。
- 限价单保留规范交易对、买卖方向、LONG/SHORT、价格和 GTC/PostOnly。市价单按原生订单号只复制一次，跟随单独立成交，不保证与主单价格相同。止损单保留触发价、`MARK_PRICE`/`CONTRACT_PRICE`、数量和持仓腿；不复制止盈、追踪止损、close-all 或其他 Algo 类型。
- `TerminalOpenOrder.time_in_force` 保留规范有效期；缺字段、有效期未知或与 `post_only` 不一致时不准入，不能把 `post_only=false` 推断为 GTC。
- 每个关系独立选择定比或定额：定比数量为主单原始委托数量 × 跟随分配资金 / KOL 策略资本 × 倍率；定额数量为该账户每笔报价币名义金额除以限价单价格、止损触发价或市价源单首次成交价，不乘倍率。开仓/增仓低于交易所最低名义额（Binance 当前常见为 5U）时向上补足最低数量和最低名义额；达到最低额后按数量步长向下取整，不得超过计划金额。旧关系默认定比。
- 单笔名义额只允许为满足交易所最低额产生必要的向上差额；达到最低额后不再多加一档。若向下取整会落到最低额以下，则仍取最小合规数量。实际名义额按签名汇率计入账户总风险；币安账户保证金要求和交易所最大数量不能因取整放宽，无法同时满足时拒绝并保留原因。例：5 USDC、DOGE/USDC 限价 0.09111、步长 1、最低额 5，得到 55 DOGE / 5.01105 USDC；计划 25 USDC、限价 0.0907 时得到 275 DOGE / 24.9425 USDC。
- 限价主单部分成交不重设子单数量。子账户独立成交，不用市价单修补主从成交差异。
- 主限价单全部成交后，已有镜像继续保留，未成交子单按原价和原数量独立等待成交，不因主单退出交易所活动订单列表而撤销。全成须由同账户、交易对、原生订单身份与方向的去重认证成交累计量等于原委托量确认，并记录到已有镜像，重启与展示历史裁剪不丢失该事实。只保留已建立的镜像，不从历史成交重新生成子单或复活已撤销/拒绝的子单。主单撤销或其他未成交终止仍撤销子单剩余量；主单修改价格/数量时，先确认旧子单终态及累计成交，再按新目标减去该来源订单已成交的子单总量生成替代单。
- 主止损单修改触发价、数量、方向或工作价格类型时，先按原生 Algo 身份撤销旧子单，签名确认终态后创建替代止损单；主止损单撤销时同步撤销。请求结果不确定时只按同一 `clientAlgoId` 精确查单，确认前不补发。
- 子单先完全成交时，同参数的源订单不会再次创建子单。
- 子单已通过精确签名查单确认后，跟随私流投影可能暂时尚未包含它；即使投影健康且观察时间更新，也不因此撤销或重建普通/止损子单。映射及原身份继续保留，主单非全成终止、参数变化或生命周期停止仍产生撤单意图。保留子单的全成可由其原生身份对应的去重认证成交累计量确认；缺少完整成交事实时保留原映射，不伪造终态。
- 平仓数量在规划和发送前受跟随账户新鲜签名持仓及已有平仓委托预留限制；不允许跨零。若开仓因最低名义额向上补足，而主账户随后以名义额在原开仓 99%–101% 内的反向限价单退出该来源仓位，则子单使用已实际建立的补足数量平仓，再按子账户持仓与已有平仓委托向下裁剪；部分主账户平仓仍按定比或定额数量处理。PM UM Hedge 普通订单不发送 `reduceOnly` 原生参数。
- 增仓继续检查单笔与总名义金额、账户事实及规则。限价必须等于源价，不以市场价替换；距离现价较远的合法挂单不会因套用市价追价规则而被重写。
- 暂停后尚有同步订单或未决命令时，不允许通过修改跟单参数切换原账户归属。

新关系使用 `baseline_json.target_model=2`。迁移将旧成交模型的活动关系置为 `needs_attention`，只取消其未发送命令；历史成交、目标、已经发送的命令与恢复事实保留。用户重新通过空仓/无挂单激活门后进入新语义。

## 持久化与执行

`venue_order_mirrors` 保存来源类型与原生订单、关系/机器人版本、子单序号、唯一 clientOrderId、数量、累计成交与状态。`venue_kol_source_market_orders` 以主账户、原生交易对和原生订单号去重市价源单。替代子单和明确失败后的新撤单均使用新命令身份；同一不确定请求始终保留原身份查询。

所有物理操作由原有单例 `venue-executor-binance` 执行；每账户串行队列上限 16，全局执行并发 32，单关系活动映射上限 1000（交易所及账户自身订单限制仍独立生效）。暂停后仍有未结清映射的跟随者继续占用 200 账户容量，未清理前不能重新激活。规划并发 8；私有投影 worker 总上限 232，为 5 KOL、200 跟随者及其他活动账户提供有界空间。没有新增账户进程、Actor、WAL 或独立 writer。

订单 ACK 不足以结束同步命令：普通订单通过精确签名查单核对身份、数量和累计成交；止损单通过当前 Portfolio Margin Algo 精确查单核对 `algoId`、`clientAlgoId`、触发价和状态。开放订单列表中消失不等于已撤销；精确查单未能确认时保持待对账，不补发。

未决命令阻止该账户新增发送，但非 Grid 账户的认证私流订单和持仓投影继续更新。Grid 的批次一致性闸门仍保留。发送前的镜像授权或源事实检查失败按明确未发送处理，不留在 `Sending`；已经进入发送边界的命令仍按原身份待对账。受信任运维可在 Executor 凭证边界内运行 `venue-executor-binance inspect-account CREDENTIAL SYMBOL`，独立核对签名账户事实及现有未决命令；该入口强制数据库只读，不启动调度、不更改命令。

新开仓命令在 `copy_risk.open_quantity_rounding` 中持久化“最低额向上、其余向下”策略；发送与同 ID 回读复用同一归一化函数，签名回执确认后记录实际子单数量，后续事实不可改变同一原生订单的数量。仅有 `round_open_quantity_up` 的旧命令继续全量向上，两个标记都缺失的历史命令保持向下，升级不重新解释历史发送。已拒绝的旧子单不自动补发；新源单/有效修改仍按正常镜像生命周期处理。平仓不使用开仓最低额补足逻辑，继续按可减持仓和已有平仓预留向下裁剪；源限价保持不变。

迁移 `0028` 增加授权/实例/映射；`0029` 开放真实 GTC 镜像并记录撤单次数；`0034` 增加多配置目录、配置版本和单活动实例约束；`0040` 增加市价源单去重、来源类型及止损命令字段。`schema.rs` 在事务中串行安装并记录版本和校验值，已执行迁移不会重复改写数据。首次升级执行既有迁移的兼容安装；此后源码中已应用迁移内容变化会拒绝启动。不得手工伪造迁移版本。

部署角色须允许 Executor 读取授权/实例、更新实例清理状态、读写映射及命令，并使用映射命令序列；授权表和审计表的写权限只授予管理员工具。Control 的迁移身份需要 DDL 权限，用户请求不能借此修改授权。角色实际配置须在部署门核验。

客户与运营会话隔离、Cookie 加密、CSRF、凭证表单和构建边界统一维护在 [Web 指南](WEB.md)。机器人接口仍在 Control 按用户归属和带单授权校验。

## 验收

必须覆盖默认拒绝、越权/版本冲突、撤权竞态、幂等、GTC/PostOnly、市价源单多成交去重、止损创建/修改/撤销、部分成交、改单先撤后挂、子单先成交、精确撤单、超时只读恢复、暂停/重启及凭证失效。数据库测试只使用显式隔离测试库；fixture 不构成实盘模式。

Web 检查登录/邀请、API 流程、隐藏入口、撤权实例、重复请求和手机布局。5/200 容量、分段延迟与目标主机资源须独立测量；100 ms 规划周期和私流发布周期不能当作实测延迟。真实 Canary、部署和旧账户切换另需明确授权，代码测试不代表这些门已通过。

KOL 原生跟单的新指令不再使用软件单笔或总名义金额上限，也不再以初始权益乘 5 限制开仓。限价、市价与 STOP_MARKET 开仓均持久化 `copy_risk.notional_limit_policy=exchange_account`；币安账户保证金、持仓/订单规则、交易所步长/最小名义额/最大数量决定准入，原权限、同一身份对账、价格保护和只减仓约束保留。定比/定额决定计划数量，定比权益仍是验证快照，取消额度不代表动态重算跟单比例。历史无此字段的指令按 `stored_limits` 原规则恢复，已拒绝指令不自动补发。旧 wire 和数据库额度列仅为历史兼容，新模式不用于开仓额度；页面移除额度输入，API 字段显示统一为“API密钥”和“密钥”。
