- VenueFlow 切回已缓存交易对或周期时复用有界已收盘 K 线、只补历史缺口，并并行建立现有两条行情连接；REST 形成中 K 线可先显示，仍不进入已收盘指标。账户订阅稳定排序，合法 SSE 帧独立续连接存活时间，底栏权益与保证金固定使用账户 USD 汇总。
- Binance 连续命令阻塞 Grid 执行投影时，将同代已认证订单、成交与仓位写入独立展示投影；Grid 派发仍依据原执行投影和对账门禁。该账户展示变化已随 `64cdfb7` 部署，执行投影与对账门禁保持独立。

- 成交历史按原生 fromId 续读时保留晚到的较早时间成交；首次时间查询、重复 ID 和成交时间倒退仍拒绝。

- 账户投影启动失败按账户退避重试（3 秒起、60 秒封顶），记录脱敏失败阶段，避免重建 worker 重置重试预算。

- Binance 账户流在仓位数量对齐后发布，成交时间领先不再冻结投影；数量缺口以单调时钟等待 5 秒后触发签名恢复。
- 签名成交回放的显示历史写入及快照 JSON 均限制为最近 500 条，保留完整签名恢复游标和执行侧成交处理。

## 历史与版本入口

早期 alpha 发布、已完成实施计划及验证流水保留在 Git 历史，按 `git log -- docs/CHANGELOG.md` 和对应版本标签查阅；它们不代表当前部署状态。

- 产品版本以 [VERSION](../VERSION) 为准；运行产物以 manifest 的完整 commit 与 SHA256 为准。
- 产品号、Rust/npm package 版本、Control 协议及数据库迁移独立演进，不因改号重写数据库或旧恢复事实。
- 构建、发布及回滚见 [开发指南](DEVELOPMENT.md#executor-release)；提交或标签不包含未提交改动，也不证明已经部署或完成实盘验收。

- 修复同一所有者删除个人凭证后转为托管时的身份冲突，保留历史账户与订单；新增固定主单比例与首次验证设置，50% 不依赖权益或策略资本，低于最低下单量不自动放大。

- 跟单准入区分持仓与挂单，允许已有仓位，激活记录签名基线且不自动交易原仓位；未结挂单和未决命令仍拦截。
