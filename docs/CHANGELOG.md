# 版本与更新说明

## 未发布

- VenueFlow 指标审计修复：OI 保留完整限流等待并跨订阅共享冷却；切换市场或周期取消未提交标注；FR 端点越界不保存 1ms 区间；AVWAP 缺口断线且不外推；Profile 极小成交量分配保持非负与守恒。未通过项目见指标验收门。
- 桌面行情按完整市场身份缓存已收盘 K 线，只补缺口；当前价、资金时钟、账户估值与历史标记使用共享展示事实。手输 USD 金额持久化，账户表格适配面板。
- Control 与 Executor 分离后台投影写入和命令连接额度；认证累计成交更新展示订单，保留执行投影、账户队列与原身份对账门。
- KOL 跟单允许已有持仓激活并保存签名基线，仍阻止开放订单和未决命令；新增按主单比例，数量向下取整且不补足最低额。
- 本人已删除个人 Binance 账户可经签名核验接续为同一 KOL 托管身份，保留历史归属；删除个人凭证保留订单外键并擦除密钥。
- 独立网格只以新的签名命令确认推进收敛期限；Gate 原生订单号与客户身份共同精确回读，已发送不确定结果仍保留原身份对账。
- 马丁统一实例预算，取整超额保留信号与止盈；签名回读失败显示账户不可用。
- 部署、签名回读、真实成交和长时间性能验收分别记录，不由离线测试代替。

- 成交历史按原生 fromId 续读时保留晚到的较早时间成交；首次时间查询、重复 ID 和成交时间倒退仍拒绝。

- 账户投影启动失败按账户退避重试（3 秒起、60 秒封顶），记录脱敏失败阶段，避免重建 worker 重置重试预算。

- Binance 账户流在仓位数量对齐后发布，成交时间领先不再冻结投影；数量缺口以单调时钟等待 5 秒后触发签名恢复。
- 签名成交回放的显示历史写入及快照 JSON 均限制为最近 500 条，保留完整签名恢复游标和执行侧成交处理。

- 汇入全部本地与已获取远程分支，保留原提交历史；版本记录不代表部署或实盘验收完成。

## v0.1.0 — 2026-09-07

- 新增 Binance 独立库存做市：每实例双边 Post Only 报价、净库存偏移、波动半价差、单腿/总量/净头寸和账户权益保护；复用单例 Executor、账户串行队列与原身份待对账边界。
- 策略分配改由用户管理，不以同账户已有 Grid/KOL/做市实例阻止启动；旧 Node 与新 Executor 的真实账户互斥仍保留。
- 图表拖动普通限价单改为确认后的“撤单并重新挂单”：旧单按原身份完成签名终态回读后，才按剩余数量释放新单；新单保留原 GTC/Post Only、方向和开平仓语义。
- 修复终端历史将其他交易所独立策略命令混入 Binance 查询而导致 503 的问题；桌面在历史刷新失败时明确标记旧的非终态回执，避免将“等待执行”误作当前状态。
- KOL 跟随命令继续以实际子单成交和签名持仓核对为准，撤单/新挂与不确定结果均不自动重发。

## 历史与版本入口

早期 alpha 发布、已完成实施计划及验证流水保留在 Git 历史，按 `git log -- docs/CHANGELOG.md` 和对应版本标签查阅；它们不代表当前部署状态。

- 产品版本以 [VERSION](../VERSION) 为准；运行产物以 manifest 的完整 commit 与 SHA256 为准。
- 产品号、Rust/npm package 版本、Control 协议及数据库迁移独立演进，不因改号重写数据库或旧恢复事实。
- 构建、发布及回滚见 [开发指南](DEVELOPMENT.md#executor-release)；提交或标签不包含未提交改动，也不证明已经部署或完成实盘验收。

- 修复同一所有者删除个人凭证后转为托管时的身份冲突，保留历史账户与订单；新增固定主单比例与首次验证设置，50% 不依赖权益或策略资本，低于最低下单量不自动放大。

- 跟单准入区分持仓与挂单，允许已有仓位，激活记录签名基线且不自动交易原仓位；未结挂单和未决命令仍拦截。
