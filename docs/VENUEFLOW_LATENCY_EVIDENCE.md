# VenueFlow 延迟证据采集

原生桌面按 `Ctrl+Shift+L` 打开采集窗，点击“开始新的有界采集”。默认关闭，仅在内存中观测已有实时路径，不发送交易、重试、REST 校时或额外账户读取。120 秒自动停止；也可提前停止。停止且帧回执收敛后，点击“导出 JSON 到剪贴板”，自行保存报告。启动新窗口会重置旧诊断样本。建议开始后关闭采集窗，保留目标图表可见，避免窗口遮挡。

同一采集最多保留 512 条完成样本、32 条未完成样本、32 个待确认请求、32 个快照接收标记、512 个去重身份和一个在途截图。市场最多每 250ms 发起一次帧读回，订单可提前触发；多个可见交易对共用该预算。容量满时导出 `dropped`，停止、切账户或五秒帧回执超时导出 `incomplete` 及有界 `unfinished_samples`；不能把缺样本当零延迟。滚动窗口可能淘汰早期订单样本，需分别采集行情和订单窗口。截图只用作匹配帧的回执，不写盘、不上传、不导出像素；仍有 GPU 读回与临时图像内存开销。

## 时间与身份

- **行情**：与展示缓存同次取样的 `last_price_event_ms`、`last_price_received_ms` 随实际最新价一起送到图表；只在 LIVE 行情的最新价线开启、位于绘制裁剪区且探测点未被其他 egui 图层覆盖时记录 `paint`。盘口心跳、历史加载、REST RTT、采集时的较新行情都不能替代该条价格事件。按交易所、订阅代次、交易对、事件与接收时间去重；这是可见最新价事件的有界取样，不是所有网络事件的分布，也不覆盖其他交易所尚未接入的 WS 能力。
- **订单**：普通终端限价动作进入 `apply_action` 时记录 `click`（最终提交动作，非硬件鼠标中断时间），按原 `request_id` 关联本地入队、HTTP 开始与响应头完成。仅匹配当前账户选择代次、账户、凭证、交易对和确切 `native_order_id`；命令账本为 Accepted/Reconciled 且当前新鲜签名投影含该挂单，实际订单线绘制时才记录 `paint`。HTTP ACK 自身无权产生挂单线；ReconcileRequired 不成功计样，必须由原身份对账收敛。撤单、替换及持仓确认动作不属于本次点击计时范围。
- **事实**：导出命令 `created_ms/updated_ms`、交易所订单 `created_ms`、账户投影 `observed_ms/persisted_ms` 和已校验完整 HTTP/SSE 快照的本地接收时间。交易所创建时间不是精确确认时间，账本 updated 也不是交易所 ACK 时间；当前协议没有独立的精确 ACK 时间戳，报告明确保留这一缺口。投影在网络线程接收并校验后打点，包含解码开销，不冒充首字节时间。
- **绘制**：`paint` 是 egui 图形提交时间，只有相同帧 token 的原生帧缓冲截图回执才能完成样本。`framebuffer_received` 包含 GPU 读回、事件派送与主线程等待，是 instrumented render 的保守上界；不是显示器扫描输出或用户肉眼感知时刻。丢弃的 egui pass 不请求读回。探测点可见性不证明整条线无遮挡；外部窗口遮挡和显示器状态仍须现场核验。

## 时钟与统计

同机点击至帧回执采用 `Instant` 单调时间，不受系统 UTC 调整影响。行情跨交易所与本机 UTC，默认仅导出原始有符号年龄，P50/P95 为空。独立核验后才能勾选校时，填写精确交易所名（如 Binance）、`本机 UTC − 交易所 UTC` 偏差、覆盖整个 120 秒窗口的误差上界，以及来源/测量 UTC/方法。可使用已验证时间同步证据或只读服务器时间请求的多次往返区间；不得把 RTT/2 直接当实测单向延迟。采集本身不会发校时请求。

`corrected = framebuffer UTC − event UTC − offset`，保守界为 `corrected + uncertainty`。负值或下界落到零以下、缺校时来源、交易所不匹配不进入跨机器分位数；不把负延迟裁成零。以窗口起点比较本机 UTC 与单调时钟，偏离超过 20ms 的行情样本无效。Control 服务器原始时间单独保留，未校正，禁止直接与本机/交易所时间相减后宣称服务端分段通过。独立核验 Control 与交易所的时钟界限后才可进一步分析这些分段。

P50/P95 使用有效保守界的 nearest-rank（向上取整）分位数，报告同时给出 eligible/excluded、丢弃和未完成数量。行情目标 P95≤300ms，订单≤1000ms；超过上界目标不证明底层实际渲染一定超时，低于目标也只证明这个带测量开销的采样边界。小样本、采样偏差、时钟不确定或未完成请求不能升级为完整 LIVE 性能验收。报告固定 `live_acceptance=NOT_RUN`，性能结果不改变交易授权或新鲜度判断。

## 验证与仍需的现场验收

安全 fixture 覆盖偏差正负号、误差界限、缺失校时、UTC 跳变、单调订单计时、nearest-rank、容量/去重、错误帧 token、帧超时、ACK 缺签名事实、ReconcileRequired、签名恢复与账户切换。合成截图事件仅验证关联契约，不能替代真实 GPU 或 LIVE 验收。

现场应记录准确源码与运行二进制、图表配置/采样率、网络路由、连接预热、屏幕刷新率、可见状态和三方时钟证据。先用正常公开行情在多个 120 秒窗口读回真实 GPU 帧，核对同事件价格及 P95，同时对比关闭采集时的开销。真实点击链仍需用户另行授权的精确 LIVE 账户与受控限价单；保存原请求、原生订单身份、签名订单状态、交易所确认依据、投影接收及可见订单线/GPU 帧，评估正常连接、拒绝、超时待对账与切账户的成功/缺失分母。若有成交，补齐签名成交、费用、终态和持仓回读；不能为获得样本重发不确定命令。必要时用屏幕录像或外部设备验证显示器扫描输出。当前实现及离线测试不构成这些验收，也不改变 LIVE-only、单 Executor、签名事实或 ReconcileRequired 边界。
